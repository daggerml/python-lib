# Contributing

Contributions should be focused, tested changes submitted as pull requests
against `master`. The repository's canonical [contributing guide](../../CONTRIBUTING.md)
covers issue reports, branch and pull-request expectations, code standards, and
the test policy.

Before changing a subsystem, use the [codebase map](codebase-map.md) and the
relevant [architecture page](README.md#architecture) to understand its
responsibility and neighboring layers. Add or update tests for changed behavior
and run the focused tests plus the appropriate broader suite.

Automated-agent instructions, documentation edit maps, and OpenSpec change
governance are maintainer workflow material. They intentionally remain outside
`docs/` in their canonical repository locations rather than being repeated in
this contributor path.
